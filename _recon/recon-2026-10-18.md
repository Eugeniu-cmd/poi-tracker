## Pass (one crossing of an intersection)
- Approach side: N / S / W / E, the direction the car drives as it
  enters the intersection. Driving north and turning right is North Right
  (the user's rule, 2026-10-18). The client's column for it is headed
  "Coming from Direction". The side is read before the turn.
- Maneuver: L (left) / St (straight) / R (right).
- Belongs to a route and a POI. Each POI has its own target (see
  "Targets per POI").
- Recorded atomically: maneuver + side in one action after the second tap.
  Neither exists alone.

## Event — the unit of storage and transfer
{ id, ts, city, route, poi, kind, side?, man?, delta?, ref?, target? }
- id — unique, generated on the tablet at tap time (UUID).
- city — id of the city this event belongs to. The queue may hold events
  from more than one city; each event goes to its own city's mailbox.
- ts — tap time (Unix, milliseconds).
- kind — 'pass' or 'target'.
- side — 'N' | 'S' | 'W' | 'E'; man — 'L' | 'St' | 'R'.
- A pass event carries side, man and delta: +1 (pass recorded) or −1
  (pass deleted); ref — only when delta = −1: id of the pass being
  deleted.
- A target event carries target: 70, 40 or 0 — the POI's new target (see
  "Targets per POI").
- On the tablet only, a target event also keeps fromType, the type it
  replaced, so that "Cancel change" can put it back (screens.md item
  47). fromType is never sent. A POI holds at most one target event that
  waits or was rejected: a new type change drops it (but see the rule on
  unanswered pushes below), and queues a new one only when the new
  target differs from the baseline's target. The new one keeps the
  dropped one's fromType.
- On the tablet only, every event also keeps routeId, the id of its
  route (see "Cities and routes"), so History and Undo last find a
  route's events whatever its code. routeId is never sent. A new event,
  a removal too, carries the route's code at the time it is recorded,
  looked up by routeId.
- Events are never edited. An event still waiting on the tablet may be
  dropped from the queue before delivery (it never reached the sheet, so
  there is nothing to reverse); a delivered event is never changed, only
  countered by a later event, and may be trimmed from the tablet by the
  History limit below.
- A rejected event never reached the sheet either, so it may be dropped
  the same way ("Delete", "Cancel removal", "Cancel change"). "Send
  again" makes it a waiting event again with the same id, and the
  mailbox applies it once, as long as it wrote no Log row for it (see
  "Mailbox").
- An event, once posted, is never dropped until an answer names it
  (applied, duplicate or rejected), whatever happened to the push that
  carried it: a push that timed out or lost the network is sent again
  first. A Delete, Undo last, type change or code change that would
  drop it waits for that answer, then applies to the result: a
  delivered pass gets a removal, a rejected one is dropped. Until then
  the screens show it as waiting.
- A pass has at most one removal that waits or was rejected. Undo last
  skips a pass that has one (screens.md item 9).
- An event keeps its city, route and POI for good, so a rejection for a
  missing tab or row is fixed in the tracker. The one exception is a
  route not checked yet (see "Cities and routes"). When its code
  changes, its waiting and rejected events are dropped and recorded
  again under the new code, with new ids and their original times,
  sides, maneuvers, targets and fromType. None of them reached the
  sheet, so nothing is counted twice. Once the route is checked, its
  code cannot change while any of its events waits or was rejected
  (screens.md item 22).

## Tablet storage (localStorage)
- baseline — per POI, per route, per city: the 7 counts and the target,
  as last pulled from that city's tracker and as advanced by delivered
  events (next bullet).
- types — per POI, per route, per city: the POI type (see "Targets per
  POI"). Kept on the tablet only and outside the baseline, so loading
  from the sheet never wipes it.
- events — the events this tablet recorded, each in one of three states:
  waiting (not yet delivered), delivered (the mailbox confirmed it) or
  rejected (the mailbox refused it, with the reason). Every event names
  its city and its route, so one queue can hold events from more than
  one city.
- When the mailbox confirms an event, the tablet folds it into the
  baseline: a pass adds its delta to the two matching counts, a target
  event replaces the POI's target. From then on the event is kept for
  History only and takes no part in the arithmetic.
- Numbers on screen = baseline + sum of waiting pass events. Loading from
  the sheet replaces the baseline and cannot count anything twice,
  because delivered events are already inside the sheet's numbers. A
  rejected event takes no part, as if it were never recorded. The type
  on screen, and the target that follows from it, is the stored type,
  which a waiting or rejected target event has already changed.
- History limit: the tablet keeps the newest 3,000 pass events (passes
  and removals). Only delivered ones are ever trimmed, oldest first. A
  waiting or rejected event is never trimmed, whatever its age. A target
  event leaves the tablet as soon as it is delivered: the baseline then
  holds the target, types holds the type, and History does not list
  sent type changes. A delivered pass whose removal waits or was
  rejected is not trimmed either. If the browser refuses to store more,
  the app trims delivered events beyond the limit and says so, and never
  drops a waiting or rejected event.
- device: the city in use, Theme ('system', 'light' or 'dark', 'system'
  by default) and Sound (on by default).
- heading: the compass's last course in degrees and the time it was
  saved (see "Heading"). Without it the next start points north, pale.
- Empty storage = clean start; the app must work correctly in that
  state.

## User's Google tracker (one per city)
- Route sheet layout: row = POI, number in column A, data from row 2;
  B,C,D,E = N,S,W,E; F,G,H = Left, Straight, Right; I..S are formulas;
  X holds the POI's target. B..H take numbers only.
- Software writes only B..H and X of route sheets, and appends to `Log`.
  The one exception is the mailbox's setupTargetColumn, run once per
  tracker from the editor: it rewrites the formulas of I, S and the
  summary's Норма to read X (see "Targets per POI").
- NEW sheet `Log` (created by the mailbox on first run): row = event,
  append-only. Columns: A id · B time · C route · D POI · E side ·
  F maneuver · G delta · H ref · I target. A pass row leaves I empty; a
  target row leaves E..H empty. The mailbox clears a row only to undo
  its own write that failed a moment before (see "Mailbox"), so an
  empty row can sit between others.
- The client's spreadsheet (Duesseldorf_Tracking_RoadNet_v1) is never
  touched.

## Mailbox (Apps Script inside the tracker, no UI)
- POST {token, action:'push', events:[…]} → {ok:true, applied:[ids],
  duplicate:[ids], rejected:[{id, reason}]}
  For each event: if its id already exists in `Log` — report it under
  duplicate and change nothing (guard against double delivery on
  retries). Otherwise apply it and report it under applied, or refuse it
  and report it under rejected with a reason. The tablet treats applied
  and duplicate alike as delivered.
- Applying a pass: add delta to the two matching B..H cells of the route
  sheet and append a row to `Log`. The event is applied whole or not at
  all: if either cell would go below 0, neither cell changes, no `Log`
  row is written, and the event is rejected (reason 'below-zero'). A
  cell that comes to 0 is left empty, not written as 0: a 0 typed by
  hand marks an impossible maneuver.
- An event id must be a UUID, else 'bad-request' (the self-test uses ids
  of its own). A removal (delta −1) must carry ref, the UUID of the pass
  it removes, else 'bad-request'. If a removal in `Log` already took out
  the pass that ref names, the removal is rejected as 'already-removed'
  and nothing changes. This holds within one push too.
- Applying a target event: write target into the POI's cell of the
  target column (see "Targets per POI") and append a row to `Log`.
- Since v1.4 the mailbox appends the `Log` row, writes the cells and
  flushes, all inside the event's own check. If anything fails, it puts
  the old cell contents back (a formula as a formula, text as text),
  clears the `Log` row carrying that event's id, and answers 'error'.
  Each undo step is tried twice, a second apart. The `Log` row is
  cleared only when every cell is back. If a cell cannot be put back,
  the row stays, so a resend answers 'duplicate' and the tablet counts
  what the sheet may hold, and column S shows a pass left half written.
  That takes two failures in a row and is the one known limit.
- A push stops taking new events after 4 minutes, because Apps Script
  ends any run at 6 and a run cut short could leave a Log row without
  its cells. Its answer then names only the events it handled, and the
  tablet sends the others again, as for an unanswered push (see
  "Event").
- Rejection reasons, one per event: 'bad-request' (malformed event or
  unknown side, maneuver or delta), 'no-route' (no sheet of that exact
  name with "POI" in A1), 'no-poi' (no row with that number in column
  A), 'text-in-cell' (one of the two cells holds text), 'below-zero',
  'already-removed' (the pass this removal names was already removed),
  'bad-target' (not 70, 40 or 0), 'error' (anything else failed for
  that event; the rest of the batch still runs).
- The mailbox leaves no Log row for an event it rejects, so that "Send
  again" applies it once. v1.3 could break this on 'error' (it wrote
  the Log row before the cells and never undid it). v1.4 undoes the
  failed event's writes, as above. The tablet still sends at most one
  removal per pass (see "Event"), and the mailbox now refuses a second
  one as well.
- A push waits up to 30 s for the script lock; if another push still
  holds it → {ok:false, error:'busy'}, and the tablet retries a few
  seconds later without telling the user.
- POST {token, action:'pull', route} → {ok:true,
  counts:{poi:[N,S,W,E,L,St,R]}, targets:{poi:target}} — one route per
  call; a missing target cell reads as 70. A route with no sheet of that
  name → {ok:false, error:'no-route'}. Text in B..H reads as 0 and is not
  reported; column S of the sheet shows it, the answer does not. Since
  v1.4 pull waits for the script lock as push does, so it never reads a
  push half done, and answers {ok:false, error:'busy'} when it cannot
  get the lock. The tablet then tries the load again a few seconds
  later, as for a busy push.
- POST {token, action:'ping'} → {ok:true, version}
- Wrong token → {ok:false, error:'auth'}. The tablet keeps every event
  waiting, sets the city's keyRejected and shows "Access key rejected"
  (screens.md item 72). While it is set, the tablet stops sending on its
  own. Saving the connection, or a ping that answers ok ("Test
  connection"), clears it and sending starts again at once. 'no-answer'
  and 'offline' leave it set. A load that answers 'auth' leaves a new
  route "Not checked yet".
- GET → {ok:false, error:'use-post', version}.

## Sync
- A tap is stored on the tablet instantly and works with no network.
- Delivery to the mailbox is automatic as soon as network is available;
  offline, events queue up and go out in a batch. No schedules ("hourly"
  etc.).
- Sending groups the queue by city and posts each group to that city's
  mailbox. A city with no mailbox configured simply keeps queuing.
- Manual edits to B..H in the tracker remain allowed; `Log` and B..H
  can then drift apart. A "Log = B..H" consistency check was dropped on
  2026-10-04: Log holds only tablet passes while B..H also holds
  hand-entered counts, so the two never match on a route started by hand,
  and column S already flags text, mismatched halves and overruns.
- "Load from sheet" pulls one route per call and replaces that route's
  baseline (counts and targets) with what the tracker holds. The user
  loads the active route from the Sync panel. A new route loads right
  after it is added, and the 'no-route' answer keeps it from being
  saved. A route never loaded loads when it is first opened. Passes
  still waiting on the tablet are kept and sent as usual: they are not
  in the sheet yet, so the loaded numbers plus the waiting passes are
  exactly right. Nothing is discarded and no warning is needed. A load
  never runs while a push is unanswered: its events may already be in
  the sheet, so the tablet first sends that push again until an answer
  names them.

## Heading (compass)
- The compass shows where the car drives (screens.md item 19). The
  user's tablet has no magnetometer, so there is no magnet and no mount
  offset. Tested in the car on 2026-10-17 (project docs
  claude/tablet-sensor-test-2026-10-17.md and claude/prototype-v19.md).
- The raw gyroscope turns the heading all the time: its rotation about
  "up", "up" being a slow average of the accelerometer, so the angle of
  the mount does not matter. The Generic Sensor API is read first,
  "devicemotion" while it is silent. Android's ready-made orientation is
  not read: on this tablet it gives only zeros.
- The gyroscope drifts about 0.02 degrees a second. The drift is measured
  and removed while the car stands (GPS below 0.3 m/s): half-second
  averages that agree within 1 degree a second for 3 s. A turn above 0.5
  degrees a second is the car creeping round a corner, not drift.
- GPS sets north, only while the car drives straight (the gyroscope saw
  less than 3 degrees in the last 2 s) at 11 km/h (3 m/s) or more. In a
  turn the GPS course lags 2 to 3 s, below 11 km/h it is noise. Each
  straight fix pulls the heading 30% of the way to the GPS course, a gap
  over 30 degrees is taken at once. With the gyroscope silent the live
  GPS course is shown.
- The motion sensors can pause without an error while something else has
  the focus. A sensor counts as working only with a reading in the last
  second, on the page's own clock. While they are silent the arrow keeps
  the last course, pale. After a pause longer than 2 s it stays pale
  until the next GPS check. Location is asked before the motion sensors
  start, and the sensors restart when the page is visible and focused
  again.
- The heading on screen is smoothed with a time constant of 0.6 s.
- The tablet keeps the last course (see "Tablet storage"), saved every
  2 s and when the page goes away. A new start shows it pale and the
  gyroscope turns it until the first GPS check. With nothing saved the
  arrow points north, pale (decided 2026-10-18).
- The side of a pass is the quarter the arrow points to (see "Pass").

## Cities and routes
- A city = { id, name, mailboxUrl, token, routes[], lastRoute, testedAt,
  testResult, sentAt, keyRejected }. Every city has its own Google
  tracker, so its own mailbox address and password. lastRoute is the
  route the working screen opens when the city is put in use. testedAt
  and testResult ('ok', 'auth', 'no-answer' or 'offline') record the
  last "Test connection". sentAt is the time of the last successful
  send. keyRejected is set by an 'auth' answer (see "Mailbox").
- A route = { id, code, poiCount, checked, loadedAt }. code and
  poiCount are typed in by hand. The route code must match the sheet
  name in that city's tracker exactly, or the mailbox finds nothing to
  write to. id is made on the tablet and never changes, and the tablet
  keys every stored value of a route by it, never by its code. checked
  is set by the route's first successful load or its first delivered
  event. Until then the route reads "Not checked yet" and its code can
  still change (see "Event"). loadedAt is the time of the last load.
- The target per POI is not a route setting: see "Targets per POI".
- Cities are never deleted automatically. Moving from one city to the next
  adds a city; the previous one keeps its routes and its baseline.
- mailboxUrl and token live on the tablet only. They never enter project
  files, prompts or chat.

## Targets per POI
- The client's rule: an intersection takes 70 passes; a POI on a straight
  road takes 40; a POI that cannot be driven (private property, closed)
  takes 0.
- Each POI carries one of six types, and the target follows from the
  type. The type also fixes which maneuvers are possible and the split
  the crew drives (field rule, 2026-10-06):
  - Intersection: Left 28, Straight 14, Right 28 (target 70).
  - No straight: Left 35, Right 35 (70).
  - No left: Straight 14, Right 56 (70).
  - No right: Left 56, Straight 14 (70).
  - Straight only: Straight 40 (40). A POI on a straight road, or an
    intersection where only Straight is possible.
  - Not drivable: none (0). The name avoids "Closed", which reads like
    "done".
  The split is a hard limit: a maneuver whose share is full takes no
  more passes, and a maneuver the type does not allow takes none.
  Approach sides have no limit. The passenger sets the type from the
  working screen, looking at the intersection, without leaving the
  screen. New POIs start as Intersection.
- "Done", the "N of T" counter, the disc lock and the progress bar follow
  the POI's own target, never a fixed 70. A not-drivable POI is locked at once.
- The type itself lives on the tablet only (see "Tablet storage"). The
  tracker holds only the target. A change of type that changes the
  target is a target event: stored on the tablet instantly, delivered
  through the same queue as passes, written by the mailbox into the
  tracker. A change between types with the same target (the four types
  at 70) sends no event.
- Loading from the sheet keeps a stored type while a target event for
  that POI waits or was rejected, since the tracker does not hold that
  change yet. Otherwise it keeps a stored type while its target equals
  the tracker's, and else the type follows the tracker's target: 70
  Intersection, 40 Straight only, 0 Not drivable. If the tablet's data is
  lost, No straight, No left and No right come back as Intersection and
  are set again. Counts and passes are not affected.
- In the tracker the target lives in column X of every route sheet, in
  every city's tracker: the first column free of the existing layout,
  never inserted between existing columns. A new tracker must keep X
  free. An empty or non-numeric X reads as 70. "To go", the БОЛЬШЕ
  status and the summary's Норма read from it instead of the fixed 70.
  The Generator is unchanged: it already emits empty rows beyond the
  passes driven, so a POI at 40 fills 40 of its 70 rows.

# POI Tracker mailbox

An Apps Script that lives inside one city's tracker spreadsheet. The
tablet app sends it passes and target changes, and it writes them into
the route sheets. It has no user interface. The contract it implements
is docs/data-model.md, section "Mailbox".

## What the tracker must have

- A native Google Sheets file. An .xlsx opened in Google Sheets has no
  Extensions > Apps Script menu. Convert it first with File > Save as
  Google Sheets.
- One sheet per route, named exactly as the route code in the app (for
  example R20890-058), with "POI" in A1 and the POI numbers in column A.
- Columns B..H on every route sheet: N, S, W, E, Left, Straight, Right.
  Numbers only.
- Column X free on every route sheet. The mailbox keeps each POI's target
  there (70, 40 or 0). An empty or non-numeric cell reads as 70. You may
  also type 40 or 0 there by hand.
- No sheet named Log. The mailbox creates it on the first push, at the
  end of the tab list, and appends to it. It clears a row only to undo
  its own write that failed a moment before (v1.4).
- File > Settings > Time zone set to the city's time zone. The Log's
  time column is shown in that zone; with the default GMT a tap at 16:43
  in Vienna reads 14:43.

## Notes for the app

- Send every request as POST with the body as plain text
  (Content-Type: text/plain) holding the JSON. Apps Script does not
  answer the browser's preflight request, so application/json fails.
- ping answers {ok:true, version}. Test connection uses it.
- Errors for the whole request: auth (wrong or missing key),
  bad-request (unreadable body or unknown action), no-route (pull for a
  route with no sheet of that name), busy (another push held the lock
  for 30 seconds, retry later), error (anything else). A GET answers
  use-post.
- pull reads text in B..H as 0 and does not report it. Column S of the
  sheet shows that error, the pull answer does not.
- Rejection reasons for a single event in push: bad-request, no-route,
  no-poi, text-in-cell, below-zero, already-removed, bad-target, error.
- Every event id is a UUID. Any other id is bad-request (v1.4).
- A removal (delta -1) must carry ref, the id of the pass it removes. A
  removal without a ref is bad-request, and a second removal of the same
  pass is already-removed (v1.4).
- After error nothing of that event stays in the tracker, so it may be
  sent again (v1.4). The one limit: if a cell cannot be put back, twice,
  the Log row stays too, so a resend answers duplicate, and column S
  shows a pass left half written.
- A push stops taking new events after 4 minutes, since Apps Script ends
  any run at 6. Its answer then names only the events it handled. Send
  the others again (v1.4).
- pull waits for a running push, like push does, and answers busy when
  it cannot (v1.4).
- The tablet treats applied and duplicate alike as delivered.
- A count that a removal brings to 0 is left as an empty cell, because
  a 0 typed by hand means "impossible maneuver".

/**
 * POI Tracker mailbox.
 * Apps Script bound to one city's tracker spreadsheet. No UI.
 * The tablet app talks to it with three actions: ping, pull, push.
 * Contract: docs/data-model.md, section "Mailbox".
 * Install steps: mailbox/README.md.
 *
 * The access key is NOT in this file. It lives in
 * Project Settings > Script properties, under the name TOKEN.
 */

var VERSION = '1.4';
var LOG_SHEET = 'Log';
var LOG_HEADER = ['id', 'time', 'route', 'poi', 'side', 'maneuver', 'delta', 'ref', 'target'];
var TARGET_COL = 24;            // column X
var SIDE_COL = { N: 2, S: 3, W: 4, E: 5 };   // columns B..E
var MAN_COL = { L: 6, St: 7, R: 8 };         // columns F..H
var TARGETS = [70, 40, 0];
var DEFAULT_TARGET = 70;
var LOCK_WAIT_MS = 30000;
var PUSH_BUDGET_MS = 240000;    // a push stops taking new events after 4 minutes (Apps Script stops a run at 6)
var FIXED_TARGET = 'Generator!$B$4';   // the old fixed 70 in tracker formulas

function doGet() {
  return reply_({ ok: false, error: 'use-post', version: VERSION });
}

function doPost(e) {
  var body;
  try {
    body = JSON.parse(e && e.postData ? e.postData.contents : '');
  } catch (err) {
    return reply_({ ok: false, error: 'bad-request' });
  }
  if (!body || typeof body !== 'object') {
    return reply_({ ok: false, error: 'bad-request' });
  }

  var expected = PropertiesService.getScriptProperties().getProperty('TOKEN');
  if (!expected || body.token !== expected) {
    return reply_({ ok: false, error: 'auth' });
  }

  try {
    if (body.action === 'ping') return reply_({ ok: true, version: VERSION });
    if (body.action === 'pull') return reply_(pull_(body.route));
    if (body.action === 'push') return reply_(push_(body.events, null));
    return reply_({ ok: false, error: 'bad-request' });
  } catch (err) {
    return reply_({ ok: false, error: 'error', message: String(err) });
  }
}

function reply_(obj) {
  return ContentService
    .createTextOutput(JSON.stringify(obj))
    .setMimeType(ContentService.MimeType.JSON);
}

/* ---------- pull ---------- */

/** pull waits for a running push, so a load never reads a push half done. */
function pull_(route) {
  var lock = LockService.getScriptLock();
  if (!lock.tryLock(LOCK_WAIT_MS)) return { ok: false, error: 'busy' };
  try {
    return pullUnlocked_(route);
  } finally {
    lock.releaseLock();
  }
}

function pullUnlocked_(route) {
  var sheet = routeSheet_(route);
  if (!sheet) return { ok: false, error: 'no-route' };

  var counts = {};
  var targets = {};
  var last = sheet.getLastRow();
  if (last >= 2) {
    var rows = sheet.getRange(2, 1, last - 1, TARGET_COL).getValues();
    for (var i = 0; i < rows.length; i++) {
      var poi = rows[i][0];
      if (!isPoiNumber_(poi)) continue;
      var seven = [];
      for (var c = 1; c <= 7; c++) {
        var v = rows[i][c];
        seven.push(typeof v === 'number' ? v : 0);
      }
      counts[poi] = seven;
      targets[poi] = readTarget_(rows[i][TARGET_COL - 1]);
    }
  }
  return { ok: true, counts: counts, targets: targets };
}

/* ---------- push ---------- */

/**
 * faultId is null for every real request. Only selfTestOnCopy passes an
 * event id there, to make that event fail after its writes and so prove
 * that the undo works.
 * A push that runs past PUSH_BUDGET_MS stops between two events. Its
 * answer names only the events it handled, and the tablet sends the rest
 * again (data-model.md).
 */
function push_(events, faultId) {
  if (!Array.isArray(events)) return { ok: false, error: 'bad-request' };

  var started = now_();   // the budget counts the wait for the lock too
  var lock = LockService.getScriptLock();
  if (!lock.tryLock(LOCK_WAIT_MS)) return { ok: false, error: 'busy' };

  try {
    var log = logSheet_();
    var known = readLog_(log);
    var ctx = { log: log, seen: known.seen, removed: known.removed, sheets: {}, rows: {},
                faultId: faultId || null };
    var applied = [];
    var duplicate = [];
    var rejected = [];

    for (var i = 0; i < events.length; i++) {
      if (now_() - started > PUSH_BUDGET_MS) break;
      var ev = events[i];
      var id = ev && typeof ev.id === 'string' ? ev.id : null;
      var result;
      try {
        result = applyEvent_(ev, ctx);
      } catch (err) {
        result = 'error';
      }
      if (result === 'applied') applied.push(id);
      else if (result === 'duplicate') duplicate.push(id);
      else rejected.push({ id: id, reason: result });
    }

    SpreadsheetApp.flush();
    return { ok: true, applied: applied, duplicate: duplicate, rejected: rejected };
  } finally {
    lock.releaseLock();
  }
}

/**
 * Returns 'applied', 'duplicate' or a rejection reason.
 * Order of writes: the Log row first, then the cells, then a flush, so a
 * failed write surfaces here and not later. If anything fails after the
 * Log row, undo_ puts the old cells back and clears that Log row, and the
 * error goes up to push_, which answers 'error'. A refused event leaves
 * no trace, so "Send again" applies it once (data-model.md).
 */
function applyEvent_(ev, ctx) {
  if (!ev || typeof ev !== 'object') return 'bad-request';
  if (!isEventId_(ev.id)) return 'bad-request';
  if (typeof ev.route !== 'string' || ev.route === '') return 'bad-request';
  if (!isPoiNumber_(ev.poi)) return 'bad-request';
  if (ev.kind !== 'pass' && ev.kind !== 'target') return 'bad-request';

  if (ctx.seen[ev.id]) return 'duplicate';

  var sheet = cachedSheet_(ev.route, ctx);
  if (!sheet) return 'no-route';

  var row = cachedRow_(ev.route, sheet, ev.poi, ctx);
  if (!row) return 'no-poi';

  var time = isFinite(Number(ev.ts)) && ev.ts !== null && ev.ts !== '' ? new Date(Number(ev.ts)) : new Date();

  if (ev.kind === 'pass') {
    var sideCol = SIDE_COL.hasOwnProperty(ev.side) ? SIDE_COL[ev.side] : 0;
    var manCol = MAN_COL.hasOwnProperty(ev.man) ? MAN_COL[ev.man] : 0;
    if (!sideCol || !manCol) return 'bad-request';
    if (ev.delta !== 1 && ev.delta !== -1) return 'bad-request';
    // a removal names the pass it removes, and a pass is removed only once
    if (ev.delta === -1) {
      if (!isEventId_(ev.ref)) return 'bad-request';
      if (ctx.removed[ev.ref]) return 'already-removed';
    }

    var range7 = sheet.getRange(row, 2, 1, 7);
    var seven = range7.getValues()[0];
    var forms = range7.getFormulas()[0];
    var oldS = seven[sideCol - 2];
    var oldM = seven[manCol - 2];
    if (!isCount_(oldS) || !isCount_(oldM)) return 'text-in-cell';

    var ns = (oldS === '' ? 0 : oldS) + ev.delta;
    var nm = (oldM === '' ? 0 : oldM) + ev.delta;
    if (ns < 0 || nm < 0) return 'below-zero';

    var cells = [[row, sideCol, oldS, forms[sideCol - 2]], [row, manCol, oldM, forms[manCol - 2]]];
    try {
      ctx.log.appendRow([ev.id, time, ev.route, ev.poi, ev.side, ev.man, ev.delta,
                         ev.delta === -1 ? ev.ref : '', '']);
      sheet.getRange(row, sideCol).setValue(cellValue_(ns));
      sheet.getRange(row, manCol).setValue(cellValue_(nm));
      SpreadsheetApp.flush();
      if (ctx.faultId === ev.id) throw new Error('self-test fault');
    } catch (err) {
      undo_(ctx, sheet, cells, ev.id);
      throw err;
    }
    ctx.seen[ev.id] = true;
    if (ev.delta === -1) ctx.removed[ev.ref] = true;
    return 'applied';
  }

  // kind === 'target'
  if (TARGETS.indexOf(ev.target) === -1) return 'bad-target';
  var xCell = sheet.getRange(row, TARGET_COL);
  var x = [[row, TARGET_COL, xCell.getValue(), xCell.getFormula()]];
  try {
    ctx.log.appendRow([ev.id, time, ev.route, ev.poi, '', '', '', '', ev.target]);
    xCell.setValue(ev.target);
    SpreadsheetApp.flush();
    if (ctx.faultId === ev.id) throw new Error('self-test fault');
  } catch (err) {
    undo_(ctx, sheet, x, ev.id);
    throw err;
  }
  ctx.seen[ev.id] = true;
  return 'applied';
}

/**
 * Undoes the writes of one failed event. Each cell gets its old content
 * back (its formula if it had one, text as text), flushed at once so a
 * failed restore shows here. Only when every cell is back is the Log row
 * that carries this event's id cleared: if a cell may still hold its new
 * value, the row stays, so a resend answers 'duplicate' and the tablet
 * and the sheet agree. The row is found by its id near the end of Log,
 * never assumed to be the last one, and cleared rather than deleted,
 * since a sheet refuses to delete its last unfrozen row. Every step is
 * tried twice, a second apart. The event is answered 'error' either way
 * (data-model.md names this limit).
 */
function undo_(ctx, sheet, cells, id) {
  var restored = true;
  for (var i = 0; i < cells.length; i++) {
    var c = cells[i];
    var done = tryTwice_(function () {
      restore_(sheet.getRange(c[0], c[1]), c[2], c[3]);
      SpreadsheetApp.flush();
    });
    if (!done) restored = false;
  }
  if (!restored) return;
  tryTwice_(function () {
    var last = ctx.log.getLastRow();
    var first = Math.max(2, last - 49);
    if (last < first) return;
    var ids = ctx.log.getRange(first, 1, last - first + 1, 1).getValues();
    for (var r = ids.length - 1; r >= 0; r--) {
      if (String(ids[r][0]) === id) {
        ctx.log.getRange(first + r, 1, 1, LOG_HEADER.length).clearContent();
        SpreadsheetApp.flush();
        return;
      }
    }
  });
}

/** Text goes back as text: an apostrophe keeps "40" from turning into 40, except in a cell formatted as plain text. */
function restore_(range, value, formula) {
  if (formula) range.setFormula(formula);
  else if (typeof value === 'string' && value !== '' && range.getNumberFormat() !== '@') range.setValue("'" + value);
  else range.setValue(value);
}

function tryTwice_(fn) {
  try {
    fn();
    return true;
  } catch (e) {
    try {
      Utilities.sleep(1000);
      fn();
      return true;
    } catch (e2) {
      return false;
    }
  }
}

/* ---------- helpers ---------- */

function isPoiNumber_(v) {
  return typeof v === 'number' && v > 0 && Math.floor(v) === v;
}

/** Event ids are UUIDs made on the tablet, or the self-test's own ids. */
function isEventId_(v) {
  return typeof v === 'string' &&
    (/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i.test(v) ||
     /^selftest-[0-9]+-[a-z0-9-]+$/.test(v));
}

function now_() {
  return new Date().getTime();
}

function isCount_(v) {
  return v === '' || (typeof v === 'number' && isFinite(v));
}

/** A count of 0 is written as an empty cell: 0 by hand means "impossible maneuver". */
function cellValue_(n) {
  return n === 0 ? '' : n;
}

function readTarget_(v) {
  return TARGETS.indexOf(v) === -1 ? DEFAULT_TARGET : v;
}

/** A route sheet is any sheet with that exact name and "POI" in A1. */
function routeSheet_(route) {
  if (typeof route !== 'string' || route === '' || route === LOG_SHEET) return null;
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName(route);
  if (!sheet) return null;
  if (sheet.getRange(1, 1).getValue() !== 'POI') return null;
  return sheet;
}

function cachedSheet_(route, ctx) {
  if (!ctx.sheets.hasOwnProperty(route)) ctx.sheets[route] = routeSheet_(route);
  return ctx.sheets[route];
}

/** Row number of a POI on its sheet, from column A. 0 if absent. */
function cachedRow_(route, sheet, poi, ctx) {
  if (!ctx.rows.hasOwnProperty(route)) {
    var map = {};
    var last = sheet.getLastRow();
    if (last >= 2) {
      var col = sheet.getRange(2, 1, last - 1, 1).getValues();
      for (var i = 0; i < col.length; i++) {
        if (isPoiNumber_(col[i][0]) && !map[col[i][0]]) map[col[i][0]] = i + 2;
      }
    }
    ctx.rows[route] = map;
  }
  return ctx.rows[route][poi] || 0;
}

function logSheet_() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var log = ss.getSheetByName(LOG_SHEET);
  if (!log) {
    log = ss.insertSheet(LOG_SHEET, ss.getNumSheets());
    log.getRange(1, 1, 1, LOG_HEADER.length).setValues([LOG_HEADER]);
    log.setFrozenRows(1);
  }
  return log;
}

/** The ids already in Log, and the passes a removal in Log already took out (column H). */
function readLog_(log) {
  var seen = {};
  var removed = {};
  var last = log.getLastRow();
  if (last >= 2) {
    var rows = log.getRange(2, 1, last - 1, 8).getValues();
    for (var i = 0; i < rows.length; i++) {
      if (rows[i][0] !== '') seen[String(rows[i][0])] = true;
      if (rows[i][6] === -1 && rows[i][7] !== '') removed[String(rows[i][7])] = true;
    }
  }
  return { seen: seen, removed: removed };
}

/* ---------- one-time setup, run from the editor ---------- */

/**
 * Run once per tracker: in the Apps Script editor pick setupTargetColumn
 * in the function list and press Run. It switches "To go" (column I), the
 * status (column S) and the summary's norm from the fixed 70 to each
 * POI's target in column X. Running it again changes nothing: cells that
 * already read column X correctly are left alone, and cells written by
 * v1.2 with the wrong argument separator are repaired.
 * The result is in the Execution log.
 */
function setupTargetColumn() {
  var sheets = SpreadsheetApp.getActiveSpreadsheet().getSheets();
  var sep = separator_(sheets);
  var report = ['Argument separator of this spreadsheet: "' + sep + '"'];
  for (var i = 0; i < sheets.length; i++) {
    var sheet = sheets[i];
    var name = sheet.getName();
    if (name === LOG_SHEET || name === 'Generator') continue;
    if (sheet.getRange(1, 1).getValue() === 'POI') {
      report.push(name + ': ' + switchRouteSheet_(sheet, sep) + ' cells written');
    } else {
      var n = switchSummarySheet_(sheet, sep);
      if (n > 0) report.push(name + ': ' + n + ' norm cells written');
    }
  }
  for (var j = 0; j < report.length; j++) Logger.log(report[j]);
  return report;
}

/**
 * Formulas come back from the spreadsheet in its own locale: "," between
 * arguments in some locales, ";" in others (Romanian, German). Read it off
 * the existing "To go" formulas, ignoring text inside quotes.
 */
function separator_(sheets) {
  for (var i = 0; i < sheets.length; i++) {
    if (sheets[i].getRange(1, 1).getValue() !== 'POI') continue;
    var last = sheets[i].getLastRow();
    if (last < 2) continue;
    var f = sheets[i].getRange(2, 9, Math.min(last - 1, 20), 1).getFormulas();
    for (var r = 0; r < f.length; r++) {
      var bare = f[r][0].replace(/"[^"]*"/g, '');
      if (bare.indexOf(';') !== -1) return ';';
      if (bare.indexOf(',') !== -1) return ',';
    }
  }
  return ',';
}

/** The target of the POI in a given row, as a formula: 40 or 0 from X, else 70. */
function targetExpr_(row, sep) {
  var x = '$X' + row;
  return 'IF(OR(' + x + '=40' + sep + 'AND(ISNUMBER(' + x + ')' + sep + x + '=0))' +
         sep + x + sep + FIXED_TARGET + ')';
}

/** A formula back in its original fixed-70 form, whatever was inserted before. */
function original_(f, row) {
  return f.split(targetExpr_(row, ',')).join(FIXED_TARGET)
          .split(targetExpr_(row, ';')).join(FIXED_TARGET);
}

function switchRouteSheet_(sheet, sep) {
  if (sheet.getRange(1, TARGET_COL).getValue() === '') sheet.getRange(1, TARGET_COL).setValue('Target');
  var last = sheet.getLastRow();
  if (last < 2) return 0;
  var n = last - 1;
  var pois = sheet.getRange(2, 1, n, 1).getValues();
  var count = 0;
  var cols = [9, 19];   // I: To go, S: status
  for (var c = 0; c < cols.length; c++) {
    var range = sheet.getRange(2, cols[c], n, 1);
    var formulas = range.getFormulas();
    var values = range.getValues();
    var out = [];
    var changed = [];
    var batchSafe = true;
    for (var r = 0; r < n; r++) {
      var f = formulas[r][0];
      var base = original_(f, r + 2);
      var want = base.split(FIXED_TARGET).join(targetExpr_(r + 2, sep));
      if (isPoiNumber_(pois[r][0]) && base.indexOf(FIXED_TARGET) !== -1 && want !== f) {
        out.push([want]);
        changed.push(r);
      } else {
        out.push([f]);
        if (f === '' && values[r][0] !== '') batchSafe = false;
      }
    }
    if (changed.length === 0) continue;
    if (batchSafe) {
      range.setFormulas(out);
    } else {
      for (var k = 0; k < changed.length; k++) {
        sheet.getRange(changed[k] + 2, cols[c]).setFormula(out[changed[k]][0]);
      }
    }
    count += changed.length;
  }
  return count;
}

/** The summary: "=$B4*Generator!$B$4" next to "=SUM('<route>'!$J$2:$J$198)". */
function switchSummarySheet_(sheet, sep) {
  var rows = Math.min(sheet.getLastRow(), 100);
  var cols = Math.min(sheet.getLastColumn(), 26);
  if (rows < 1 || cols < 2) return 0;
  var formulas = sheet.getRange(1, 1, rows, cols).getFormulas();
  var norm = /^=\$B(\d+)\*Generator!\$B\$4/;
  var done = /^=SUM\('((?:[^']|'')+)'!\$J\$(\d+):\$J\$(\d+)\)$/;
  var count = 0;
  for (var r = 0; r < rows; r++) {
    for (var c = 0; c < cols - 1; c++) {
      var f = formulas[r][c];
      var head = norm.exec(f);
      if (!head) continue;
      var m = done.exec(formulas[r][c + 1]);
      if (!m) continue;
      var x = "'" + m[1] + "'!$X$" + m[2] + ':$X$' + m[3];
      var base = head[0];
      var known = [base, base + normTail_(x, ','), base + normTail_(x, ';')];
      if (known.indexOf(f) === -1) continue;   // hand-edited: leave it alone
      var want = base + normTail_(x, sep);
      if (want === f) continue;
      sheet.getRange(r + 1, c + 1).setFormula(want);
      count++;
    }
  }
  return count;
}

function normTail_(x, sep) {
  return '-COUNTIF(' + x + sep + '40)*(' + FIXED_TARGET + '-40)' +
         '-COUNTIF(' + x + sep + '0)*' + FIXED_TARGET;
}

/* ---------- self-test, run from the editor on a COPY of a tracker ---------- */

/**
 * Proves the undo and the guard against a second removal, on a copy of a
 * tracker only. It refuses to run unless the script property SELFTEST
 * holds this spreadsheet's own id (the long code between /d/ and /edit in
 * its address), which a copy never shares with the original.
 * It uses the first POI on any route sheet whose N and Left cells hold a
 * number above 0 or nothing. A pass that fails after its writes must
 * change nothing, the same pass then applies (N, Left and Log rows +1), a
 * resend is a duplicate, its removal applies (back to the start), a
 * second removal is refused, and a type change that fails after its
 * write must leave X as it was. The result is in the Execution log, one
 * line per step, and a last line ALL PASS or FAILED.
 */
function selfTestOnCopy() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  if (PropertiesService.getScriptProperties().getProperty('SELFTEST') !== ss.getId()) {
    Logger.log('Refused: on a copy, set the script property SELFTEST to this spreadsheet\'s id.');
    return 'refused';
  }
  var sheet = null;
  var row = 0;
  var sheets = ss.getSheets();
  for (var i = 0; i < sheets.length && !sheet; i++) {
    var sh = sheets[i];
    if (sh.getName() === LOG_SHEET || sh.getRange(1, 1).getValue() !== 'POI') continue;
    var last = sh.getLastRow();
    if (last < 2) continue;
    var vals = sh.getRange(2, 1, last - 1, 6).getValues();
    for (var r = 0; r < vals.length; r++) {
      var n = vals[r][1];
      var l = vals[r][5];
      if (isPoiNumber_(vals[r][0]) && (n === '' || (typeof n === 'number' && n > 0)) &&
          (l === '' || (typeof l === 'number' && l > 0))) {
        sheet = sh;
        row = r + 2;
        break;
      }
    }
  }
  if (!sheet) {
    Logger.log('FAILED: no route sheet has a POI whose N and Left hold a number above 0 or nothing');
    return 'FAILED';
  }
  var route = sheet.getName();
  var poi = sheet.getRange(row, 1).getValue();

  var stamp = 'selftest-' + now_();
  var pass = { id: stamp + '-pass', ts: now_(), route: route, poi: poi, kind: 'pass', side: 'N', man: 'L', delta: 1 };
  var removal = { id: stamp + '-removal', ts: pass.ts, route: route, poi: poi, kind: 'pass', side: 'N', man: 'L', delta: -1, ref: pass.id };
  var again = { id: stamp + '-removal-2', ts: pass.ts, route: route, poi: poi, kind: 'pass', side: 'N', man: 'L', delta: -1, ref: pass.id };
  var target = { id: stamp + '-target', ts: pass.ts, route: route, poi: poi, kind: 'target', target: 40 };

  function count(v) { return v === '' ? 0 : v; }
  function snap() {
    return { n: count(sheet.getRange(row, 2).getValue()), l: count(sheet.getRange(row, 6).getValue()),
             x: sheet.getRange(row, TARGET_COL).getValue(), log: logSheet_().getLastRow() };
  }
  function show(s) { return 'N ' + s.n + ', Left ' + s.l + ', X ' + (s.x === '' ? 'empty' : s.x) + ', Log rows ' + s.log; }
  var lines = ['POI ' + poi + ' on ' + route + ' (row ' + row + ')'];
  var ok = true;
  function step(name, events, faultId, want, dn, dl, dlog) {
    var before = snap();
    var res = push_(events, faultId);
    var got = !res.ok ? res.error :
              res.applied.length ? 'applied' :
              res.duplicate.length ? 'duplicate' : res.rejected[0].reason;
    var after = snap();
    var good = got === want && after.n === before.n + dn && after.l === before.l + dl &&
               after.x === before.x && after.log === before.log + dlog;
    if (!good) ok = false;
    lines.push((good ? 'PASS ' : 'FAIL ') + name + ': answer ' + got + ' (want ' + want + '). ' +
               show(before) + ' -> ' + show(after));
  }
  var start = snap();
  step('a pass that fails after its writes changes nothing', [pass], pass.id, 'error', 0, 0, 0);
  step('the same pass sent again applies', [pass], null, 'applied', 1, 1, 1);
  step('the same pass once more is a duplicate', [pass], null, 'duplicate', 0, 0, 0);
  step('its removal applies', [removal], null, 'applied', -1, -1, 1);
  step('a second removal of the same pass is refused', [again], null, 'already-removed', 0, 0, 0);
  step('a type change that fails after its write leaves X as it was', [target], target.id, 'error', 0, 0, 0);
  var end = snap();
  var back = end.n === start.n && end.l === start.l && end.x === start.x;
  if (!back) ok = false;
  lines.push((back ? 'PASS ' : 'FAIL ') + 'N, Left and X end as they started. Two Log rows stay: the test pass and its removal.');
  lines.push(ok ? 'ALL PASS' : 'FAILED');
  for (var j = 0; j < lines.length; j++) Logger.log(lines[j]);
  return ok ? 'ALL PASS' : 'FAILED';
}

## 8. Working rules learned

- Numbers only in B..H of tracker route sheets; text corrupts the
  generator silently (28+11 POIs damaged in Dortmund this way).

  from the tracker's F,G,H = Left,Straight,Right; never transfer in
  one paste.
